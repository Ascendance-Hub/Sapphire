# Site en/pt-br Internationalization — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Sapphire docs website bilingual — English (default) and Brazilian Portuguese — with a flag switcher, including a full pt-br translation of all 26 documentation pages.

**Architecture:** Astro native i18n routing — English keeps the current URLs, pt-br is served under a `/pt-br/` prefix; both are statically generated. English docs stay at `docs/**`; pt-br translations are added at `docs/pt-br/**`. A strings dictionary drives the translated chrome; a flag switcher in the nav (emoji) toggles locale and the choice is remembered in `localStorage`.

**Tech Stack:** Astro 5, TypeScript, the existing `remark` doc-link rewriter, `vitest` (website tests live in `website/tests/`).

**Source spec:** `docs/superpowers/specs/2026-05-16-site-i18n-design.md`

- [ ] **Step 3: Make `rewriteDocLink` locale-aware**

In `website/src/lib/remark-rewrite-links.ts`, replace the body of `rewriteDocLink` after the `escaped` check so a `pt-br/`-prefixed slug becomes a `/pt-br/docs/` route:

```ts
  if (escaped) return url

  let slug = segments.join('/').replace(/\.md$/, '')
  // README.md is the docs index
  slug = slug.replace(/(^|\/)README$/i, '')

  // A pt-br doc's resolved slug starts with `pt-br/`; that becomes a
  // `/pt-br/docs/...` route rather than `/docs/pt-br/...`.
  const cleanBase = base.replace(/\/$/, '')
  let localePrefix = ''
  if (slug === 'pt-br' || slug.startsWith('pt-br/')) {
    localePrefix = '/pt-br'
    slug = slug.slice('pt-br'.length).replace(/^\//, '')
  }

  const route = slug
    ? `${cleanBase}${localePrefix}/docs/${slug}`
    : `${cleanBase}${localePrefix}/docs`
  return anchor ? `${route}#${anchor}` : route
```

The `transformer` function needs no change — its regex `/\/docs\/(.+)\.md$/i`
already yields `fromSlug = 'pt-br/concepts/overview'` for a pt-br vfile, and the
relative-path resolution keeps the `pt-br/` prefix in `segments`.
